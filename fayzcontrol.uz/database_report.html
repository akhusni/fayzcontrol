⚙️ 1. Storage Engine & System Architecture

Reliability, Concurrency, and Multi-Engine Strategy

The system is architected for zero-data-loss healthcare operations. It handles dual-engine execution:

Dual-Engine Resilience Layer (db.py): In production on fayzcontrol.uz, the backend connects natively to MySQL 8.0.45. During offline development on a local computer without MySQL running, it falls back seamlessly to SQLite 3 (WAL Mode). Developers write single-standard ANSI SQL queries, and db.py transparently handles query translation (? into %s) and row mapping.
Architecture Pillar Specification Clinical & Operational Benefit
Storage Engine InnoDB Full ACID transaction safety. Crash recovery via Write-Ahead Log (WAL) and Redo logs.
Concurrency Model Row-Level Locking & MVCC Cashiers can settle invoices while nurses record vitals and doctors prescribe meds simultaneously without table lockups.
Isolation Level REPEATABLE READ Prevents dirty reads and phantom updates during simultaneous bed reservation.
Character Encoding utf8mb4 / utf8mb4_unicode_ci Complete multi-lingual fidelity: Uzbek (Latin & Cyrillic), Russian, English, medical symbols, and emojis.

🛡️ 11. Security, Backups & Disaster Recovery

Maintenance commands and production backup strategy

To back up the MySQL database on the production server (31.184.242.14):

# 1. Complete Compressed Backup (Including Triggers, Routines & Views)
mysqldump -u fayzhouse -p --routines --triggers --single-transaction fayzhouse | gzip > /var/backups/fayzhouse_backup_$(date +%Y%m%d_%H%M%S).sql.gz

# 2. Instant Disaster Recovery (Restore from Backup)
gunzip < /var/backups/fayzhouse_backup_YYYYMMDD.sql.gz | mysql -u fayzhouse -p fayzhouse
