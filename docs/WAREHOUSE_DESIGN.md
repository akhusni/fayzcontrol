# Medical warehouse — design (2026-10-10)

Extends the existing medicine stock; it does not replace it. One source of truth for every agent working on this feature.

## What exists today (do not duplicate)
- `medications_catalog` (id MED-…, name, category, form, standard_dosage, `unit_price` = what the PATIENT is billed per unit, `stock_quantity INT`, `min_stock_level INT default 10`, `is_active`). This becomes the **inventory item**. Its id stays (prescriptions.medication_id, medication_purchases and aliases point at it).
- `prescriptions.medication_id` (FK) + dosage/route/frequency/duration. No prescribed quantity yet.
- `medication_administrations` (nurse doses, `nursery.py`): each given dose takes `stock_units` off `medications_catalog.stock_quantity` directly.
- `POST /api/accounting/invoice-items` (accounting): a medicine bill line takes stock off the shelf directly.
- `POST /api/accounting/medication-purchases` (+ DELETE): adds stock, writes `medication_purchases` and an `accounting_transactions` expense (category `medication_purchase`), but also OVERWRITES `unit_price` (the patient price) with the purchase price. That conflation is a defect: purchase cost and patient price are different things.
- `v_pharmacy_low_stock` uses `<=`; the spec says low = strictly below.
- Roles: `pharmacist` (module `pharmacy`), `accountant` (`accounting`), doctors (`doctors`), nurse (`nursery`), `owner`, superadmin `*`. `permissions.API_RULES` is default-deny.

## Principles
1. Stock changes ONLY through `inventory.py` service functions, each writing an immutable ledger row (`inventory_transactions`) in the same DB transaction. No other code may `UPDATE medications_catalog SET stock_quantity` or `inventory_batches.remaining_qty` (the existing direct updates in server.py/nursery.py are migrated to the service).
2. Base unit: every quantity is stored in the item's **base (dispensing) unit** (tablet, ml, piece, ampoule, vial…) as `DECIMAL(14,3)`. Items with `allow_fraction=0` accept integer quantities only. Packages are a purchasing convenience: `units_per_package` converts packages→base units at receipt time.
3. Money: `decimal.Decimal` everywhere; unit cost `DECIMAL(18,4)`, totals `DECIMAL(18,2)`, ROUND_HALF_UP. Never float.
4. Three different amounts, never mixed: **purchase cost** (what we paid), **valuation** (qty × weighted-average cost), **patient price** (`unit_price`, per base unit; purchases must NOT touch it).
5. Costing method: **weighted average** per item. On receipt: `new_avg = (on_hand*avg + recv_qty*recv_unit_cost) / (on_hand + recv_qty)` (4 dp). Outgoing movements are valued at the average at that moment. Receipt reversal removes the received quantity at its receipt unit cost and recomputes the average from remaining value. Stock value = on_hand × avg_unit_cost (2 dp). Report value split: total on hand, of which expired, available (non-expired).
6. Prescribing never changes stock. Stock leaves only at dispensing/administration/billing.
7. Draft receipts never change stock. Posting is one atomic transaction (receipt lines → batches → ledger → item balances/avg cost → accounting expense → alerts).
8. Idempotency: `client_request_id` (UNIQUE) on receipts, dispensings and adjustments; a repeat returns the original result (`duplicate: true`, HTTP 200) and changes nothing.
9. Concurrency: lock the item row (`SELECT … FOR UPDATE`) then its batches in `id` order inside the transaction; the global `WRITE_LOCK` already serialises writes in one process, the row locks protect against several.
10. Dispensing batch choice: **FEFO** (earliest expiry first; batches without expiry last, ordered by received_at = FIFO). Expired batches (expiry_date < today) are never used. No exception path in v1.
11. Ledger is append-only: DB triggers refuse UPDATE/DELETE on `inventory_transactions`; corrections are reversal rows (`reversal_of`). A transaction can be reversed once.
12. Low stock: `available_qty < min_stock_level` (strict). Out of stock: `available_qty <= 0`. `min_stock_level` default **10** comes from setting `inventory.default_min_stock` (table `inventory_settings`), not a literal in code; per-item value editable by accounting. Expiry warning window default 30 days (`inventory.expiry_warning_days`).
13. All user-facing text Uzbek (Latin); comments/docstrings English; errors `400 {"error": "<Uzbek>", "field": …}` via `_send_validation_error`.

## Data model (migration `inventory.ensure_schema(conn)`, idempotent, also mirrored in `data/schema.mysql.sql`)
`medications_catalog` gets (nullable unless noted): `sku` (UNIQUE), `barcode`, `generic_name`, `strength`, `manufacturer`, `item_type` NOT NULL default 'medicine' CHECK in (medicine, vitamin, injection, syringe, consumable, equipment, other), `description`, `base_unit` NOT NULL default 'dona', `package_unit`, `units_per_package` DECIMAL(14,3) NOT NULL default 1 CHECK >0, `allow_fraction` TINYINT default 0, `track_expiry` TINYINT default 0, `supplier_id`, `last_package_price` DECIMAL(18,2), `last_unit_cost` DECIMAL(18,4), `avg_unit_cost` DECIMAL(18,4) NOT NULL default 0, `updated_at`. `stock_quantity` → DECIMAL(14,3) (cached on-hand = SUM of batch remaining = ledger balance), `min_stock_level` → DECIMAL(14,3). Existing rows: base_unit derived from `form` where obvious (tabletka→tablet, ampula→ampoule, …) else 'dona'; `avg_unit_cost` stays 0 and `units_per_package` 1 (the PO/accountant fills real costs; do not invent costs). Existing positive stock gets one opening batch (batch_no 'OCHILISH', no expiry, cost 0) plus an `opening` ledger row so the ledger reconciles.
New tables: `inventory_suppliers`, `inventory_settings`, `inventory_receipts` (draft|posted|reversed|cancelled, `client_request_id` UNIQUE, `accounting_transaction_id` FK → accounting_transactions), `inventory_receipt_lines`, `inventory_batches` (remaining ≥ 0 CHECK), `inventory_transactions` (ledger; `txn_type` receipt|dispense|adjustment_in|adjustment_out|supplier_return|patient_return|writeoff|reversal|opening; signed `qty_delta`, item `balance_before/after`, `unit_cost`, `value_delta`, patient/prescription/consultation/admission/receipt/dispensing/supplier/accounting refs, `performed_by`, `reason`, `notes`, `reversal_of` UNIQUE), `inventory_dispensings` (+ `inventory_dispensing_batches`; `source` manual|nurse_round|billing; `client_request_id` UNIQUE; status completed|reversed; snapshot of dosage/frequency/instructions and prescribing doctor), `inventory_alerts` (type low_stock|out_of_stock|expired|expiring_soon, status active|resolved, one active row per item+type+batch). `prescriptions` gets `quantity_prescribed DECIMAL(14,3) NULL` and `quantity_unit VARCHAR(32) NULL`. `v_pharmacy_low_stock` rebuilt with `<`.

## API (all under `/api/warehouse`, JSON)
Reads (module `warehouse` read, or `pharmacy`/`accounting`/`doctors`/`nursery` read for the first two):
- `GET /availability?q=&limit=` — prescribers: id, name, generic_name, strength, form, base_unit, available_quantity, stock_status. NO cost fields.
- `GET /summary` — items_total, units_by_unit [{unit, qty}], total_value / expired_value / available_value (cost-permitted roles only), low_stock_count, out_of_stock_count, expired_count, expiring_count, recent_receipts, recent_dispensings, settings.
- `GET /items?q=&category=&item_type=&status=ok|low|out|expired|expiring&supplier_id=&active=&sort=&dir=&limit=&offset=` → `{items, total}`; row fields: id, sku, barcode, name, generic_name, item_type, category, strength, form, manufacturer, base_unit, package_unit, units_per_package, allow_fraction, track_expiry, supplier_id/name, min_stock_level, stock_quantity, available_quantity, expired_quantity, nearest_expiry, stock_status, shortage, unit_price (patient price), is_active; cost fields last_package_price, last_unit_cost, avg_unit_cost, stock_value only for cost-permitted roles.
- `GET /items/<id>` (+ batches, last ledger rows), `GET /suppliers`, `GET /receipts?from&to&supplier_id&status`, `GET /receipts/<id>`, `GET /dispensings?patient_id&item_id&from&to`, `GET /prescriptions/pending?patient_id=` (active prescriptions with a warehouse item: prescribed, dispensed so far, remaining), `GET /transactions?item_id&type&from&to&patient_id&limit&offset`, `GET /alerts?status=active`, `GET /reconciliation`, `GET /reports/<name>?from&to&format=json|csv` with names stock, low-stock, out-of-stock, expiry, valuation, valuation-by-category, receipts, dispensings, adjustments, movement (needs item_id), reconciliation.
Writes:
- `POST /items`, `PUT /items/<id>` (non-cost fields: warehouse or accounting write; cost/pricing fields and threshold: accounting write only), `PUT /items/<id>/threshold {min_stock_level}` (accounting write), `POST /items/<id>/deactivate|activate`, `POST /suppliers`.
- `POST /receipts` (accounting write) `{client_request_id, supplier_id|supplier_name, invoice_number, receipt_date, payment_method, notes, post: bool, lines:[{item_id | new_item:{…}, packages, package_price, batch_no, expiry_date}]}`; `POST /receipts/<id>/post`, `/cancel` (drafts), `/reverse {reason}` (posted; refused when stock from its batches was already used beyond what remains).
- `POST /dispense` (warehouse write or nursery write) `{client_request_id, patient_id, prescription_id?, admission_id?, consultation_id?, item_id?, quantity, notes}`; medicine/vitamin/injection need a valid active prescription for that patient and item; consumables/syringes/equipment may reference an admission or consultation instead. Rejects cancelled/completed/held prescriptions, quantity > available (non-expired) stock, quantity > prescription remaining unless the prescription has no `quantity_prescribed`. Returns the dispensing with batches used.
- `POST /dispensings/<id>/reverse {reason}`, `POST /adjustments {client_request_id, item_id, batch_id?, kind: increase|decrease|writeoff|supplier_return|patient_return, quantity, reason (required), supplier_id?}`, `POST /transactions/<id>/reverse {reason}`.

## Permissions
- Module `warehouse` (new, in `permissions.MODULES`/`PAGE_RULES` page `/warehouse.html`, `FMH_MENU` entry in `js/fmh_dialogs.js`): `pharmacist` = `warehouse` (read+write); `accountant` = `warehouse` (they need the page; their extra rights come from `accounting` write on receipts/costs/threshold); `ward_manager`, `chief_doctor`, `owner` = `warehouse:read`; superadmin `*`; doctors/nurse get only the availability read (existing `doctors`/`nursery` modules) and nurse write on `/dispense` through the nurse round (service-level, not a route).
- Cost fields and valuation are returned only to accounting-write, owner, and superadmin (pharmacists see quantities, expiry and thresholds but not costs).
- Every route has a rule in `API_RULES` (default deny); stock-changing routes are checked by the backend, never only hidden in the UI.

## Existing code migrated onto the service
`nursery.py` dose given/undone (ledger `dispense`, source `nurse_round`), `POST /api/accounting/invoice-items` medicine lines (source `billing`), `POST/DELETE /api/accounting/medication-purchases` (the POST becomes a posted receipt via the same service; it must no longer touch `unit_price`; DELETE becomes a receipt reversal), patient delete cleanup, `/api/accounting/medicine-links` untouched. Existing tests for these must keep passing (adjust only where behaviour intentionally changed, e.g. purchases no longer overwrite `unit_price`).

## Patient history
`inventory_dispensings` is the patient's dispensing history (what was ACTUALLY given: item, quantity, unit, dosage/instructions snapshot, prescription/consultation refs, prescribing doctor, dispenser, batch/lot, status/reversal). Served by `GET /dispensings?patient_id=`; shown on the doctor page and the patient card. Nothing is added to history before the dispensing transaction commits.

## Implementation notes (W1a, 2026-10-10) — where the code differs from or adds to the text above
Code: `inventory.py` (service, no HTTP), `warehouse_api.py` (routes; `server.py` only hands over and writes the answer), tests `WarehouseStock/Dispensing/AlertsAndLedger/Access` in `tests/test_clinic.py`.

**Deviations**
1. `POST /dispense` is `warehouse:write` only (route-level). The design text said "warehouse write or nursery write" in one place and "service-level, not a route" for the nurse in another; the stricter reading was taken: a nurse reaches stock through `inventory.dispense(..., source='nurse_round')` from the nurse round, not through this route.
2. `admin` role also gets the `warehouse` module (it already has `pharmacy` + `accounting`).
3. Receipt reversal **deletes** the linked `accounting_transactions` expense (as the old `DELETE /medication-purchases` did) instead of posting a counter-income, because an income row would inflate the owner's income report. The receipt keeps `accounting_transaction_ref` (the id), the reversal reason and the ledger reversal rows; `audit_logs` has the call.
4. The prescription/patient/consultation/admission references on dispensings and ledger rows are plain indexed columns, **not foreign keys**, and dispensings carry a `patient_name` snapshot. Deleting a patient or a prescription (the tests and the clinic do both) must not be blocked by, or rewrite, append-only history.
5. Extra columns: `inventory_transactions.source` + `operation_id` (groups the lots of one dispensing/adjustment/receipt; also what `client_request_id` of an adjustment is stored next to), `inventory_receipts.accounting_transaction_ref`, `inventory_alerts.batch_key/active_marker` (unique key "one active alert per item+type+batch"). Ids: suppliers `SUP-#####`, receipts `RCP-#####`, dispensings `DSP-#####`, items `MED-#####`; batches, ledger rows, lines and alerts are numeric.
6. `GET /settings` was added (units, item types, thresholds) for the page. `client_request_id` is **required** on `POST /dispense` and `POST /adjustments` (400 `client_request_id` otherwise); optional on receipts.
7. Receipt lines may carry a one-off `units_per_package` (does not change the item) and `new_item:{...}` (creates the item inside the same transaction).
8. `POST /api/doctor/prescriptions` accepts optional `medication_id` (validated against the catalogue), `quantity_prescribed`, `quantity_unit`. Without a `medication_id` the item is found like the nurse round does (exact name, then `medication_aliases`); a prescription whose drug maps to no item is refused at dispensing ("link it first" via `/api/accounting/medicine-links`).
9. Status precedence in `stock_status`: `out` > `low` > `expired` > `expiring` > `ok`. `?status=expired|expiring` filter on the quantities, so an item that is also low still appears under them.
10. Purchase cost of **opening stock is 0** (unknown, not invented), so the first real receipt averages with it; the accountant should post an adjustment/receipt for the real opening value if valuation matters.

**Operations**
- Creating the append-only triggers needs the TRIGGER privilege and, with binary logging on, `log_bin_trust_function_creators=1` (or SUPER). The app user on the dev machine lacks it: `inventory.ensure_schema` logs `trigger ... failed` and continues. An administrator must run the two `CREATE TRIGGER trg_inv_txn_no_*` statements from `data/schema.mysql.sql` once (the suite's append-only test fails until they exist).
- `inventory.ensure_schema` runs at startup (own step) and also refreshes the low-stock/expiry alerts; `GET /alerts` and `GET /summary` refresh them again, because expiry changes with the calendar.

**Service API for the migrations (W1b)** — all take the open connection and never commit; the caller commits after success and rolls back on any exception. Business refusals raise `inventory.InventoryError(message, field, status)`.
- `dispense(conn, data, actor, source='manual'|'nurse_round'|'billing')`, `data = {client_request_id, patient_id, prescription_id?, admission_id?, consultation_id?, item_id?, quantity, notes}`; returns the dispensing (`duplicate: true` when the client id was seen). Only `source='manual'` insists on a prescription for medicines; `nurse_round` should pass the prescription id, `billing` may pass none. Use deterministic client ids (e.g. `nurse-<rx>-<date>-<slot>`) so a re-save is idempotent; find your own row again with `find_dispensing_by_client_id`, undo with `reverse_dispensing(conn, id, reason, actor)`.
- An empty shelf raises `InventoryError(field='quantity')`; the nurse path decides whether to record the dose anyway (it used to).
- `create_receipt(conn, data, actor, post=True, payment_method=<normalized>, account_source_fn=server.account_source_for)` is what `POST /medication-purchases` becomes; `reverse_receipt(conn, id, reason, actor)` is what its DELETE becomes. Neither touches `unit_price`.
- `actor = {'username':…, 'staff_id':…}`.
- Known drift until W1b lands: the old direct `UPDATE medications_catalog SET stock_quantity` paths change the cached balance without lots or ledger rows. `GET /reconciliation` reports exactly those items; availability and dispensing use the lots.
